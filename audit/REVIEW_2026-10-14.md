# Native component review — 2026-10-14

Scope: candidate **0.54-dev1**, tested binary SHA-256
`fa93e14441fd43af74e982446c6124b44e33e4acddfcbed1ed31b465a2f75bb7`.
This is an internal source review with standalone reproductions, not an
independent security certification. Runtime code and the binary were not
changed by this review. Findings below are still open.

## Findings, ordered by priority

1. **P1 — Function fingerprints do not establish the full engine ABI.**
   `probe.cpp:141-154`, `capture.cpp:36-47`, `compatibility.cpp:28-54`.
   Five function bodies are checked, but external callees, vtables and object
   layouts are not. `ReadMacro` calls slot +0x20 of the interface at object+0x30
   after checking only image address bounds. SEH cannot undo side effects of
   calling the wrong function. A data-only mutation of the callee at RVA
   0x3dde10, called at 0x6082e0, was accepted by all five profiles. A synthetic
   unprofiled metadata function was also called twice. Neither test executes
   modified game code or establishes that a specific real patch crashes.
   Review getter identity/layout assumptions and call relationships before
   claiming support for unknown builds; test another real executable.

2. **P1 — Bundled MinHook 1.3.3 ignores thread-enumeration/suspension failures.**
   `third_party/minhook/src/hook.c:263-328`, `probe.cpp:164-174`.
   Standalone fault injection made CreateToolhelp32Snapshot fail, then made
   SuspendThread fail in a separate run. MH_EnableHook still returned MH_OK
   in both. This permits code patching without establishing that other
   threads are paused. A race/crash in X4 was not reproduced. Update and
   retest the dependency; upstream [1.3.4 release notes](https://github.com/TsudaKageyu/minhook/releases/tag/v1.3.4)
   specifically address error handling in this area.

3. **P2 — The native-to-Lua marker buffer silently drops burst contacts.**
   `probe.cpp:185-197` drains up to 128 entries into 32 marker slots before
   Lua can consume them. A 128-contact burst retained only sequences97-128,
   while CaptureStats.dropped stayed0. This is75% loss in that test burst,
   not a measured loss rate for ordinary battles. The nominal output ceiling
   is about320 contacts/s before downstream Lua limits. Align drain/output
   capacity and count losses at every stage.

4. **P2 — No contact age limit or explicit session queue reset.**
   `capture.cpp:8-9,145-150`, `probe.cpp:182-224,282-309`.
   QPC timestamps are captured but not used to expire contacts. A delayed
   consumer still received a contact aged654.7ms. The pinned module retains
   queues/start state across Lua reloads; no stop/reset API is exposed for
   game-session boundaries. Add an age limit and explicit lifecycle handling.
   This is not proof of the cause of the historical first-hit visual delay.

5. **P2 — Malformed finite geometry can produce a successful NaN projection.**
   `fleet_shell.cpp:133,146-148,160-192,221-225`.
   A valid small face plus a face at finite coordinates ±1e30 passes tree
   validation, overflows float arithmetic and makes ProjectFleetIncoming
   return true with NaN coordinates/distance. Encoding then converts NaN to
   an integer. Add bounds and finite-result checks. This requires erroneous
   local geometry; it was not observed with the installed fleet.

6. **P2 — Cold geometry loading and failed retries run synchronously on the UI path.**
   `fleet_shell.cpp:108-144`, `probe.cpp:243-259`.
   Initial queries read/allocate/validate a mesh; failed meshes are not
   negatively cached. Per-profile limits allow hundreds of MB and there is
   no aggregate cache budget. Current-game stall cost was not measured in
   this review. Add realistic limits, load timing and bounded retry/preload.

7. **P2/P3 — Partial failures are not fully isolated or clearly reported.**
   `probe.cpp:99-101,149-159,173-180,261-274,292-293`.
   ACTIVE can mean only one hook succeeded. Some addon string/set allocations
   are outside exception guards. A late initialization exception does not
   reset the partially published compatibility state. Real OOM was not
   induced. Publish initialization transactionally, contain C++ exceptions
   at Lua boundaries, and report individual channel state.

## Additional limits

- Missile mid-function unwind behavior and upper AVX-register preservation
  are not established by the present ABI fixtures; do not infer a confirmed
  crash from that coverage gap.
- Lua-facing state assumes a single UI thread. Only the capture queue is
  synchronized. Document or enforce that contract.
- MAX_PATH truncation is not checked separately from failure.
- Detailed logs include addresses and raw game-state bytes when enabled.
  They are disabled by default and bounded, but should be reviewed before sharing.
- Reviewed source has no networking, external-program launch, save editing or
  on-disk EXE patching. The tested DLL imports KERNEL32 and bcrypt. This does
  not prove the safety of any other binary with the same filename.

## Positive checks

- Both exported capture/ABI tests passed, including concurrent producers,
  invalid reads, queue overflow, LastError and continued capture.
- All286 installed geometry profiles were exercised by directional BVH vs
  independent brute ray and nearest fallback tests (235base +35SVE +16TC;
  three selected samples/profile, not every possible point).
- Invalid triangle indices, cyclic BVH and NaN vertices were rejected during
  lazy mesh loading; invalid quantization was rejected at registration.
- Addon IDs reject path separators/traversal; duplicate profile IDs cannot
  replace an existing registration.
- DllMain performs no I/O/hook setup/waiting; module pinning prevents unload
  while hooks remain installed. Capture does not wait for the queue lock.

## Reproducing the isolated checks

From the repository root, with the same Windows/MSVC prerequisites as the main build:

```powershell
cmake -S audit/repro -B out-review -G "Visual Studio 17 2022" -A x64
cmake --build out-review --config Release
out-review/Release/runtime_review.exe
out-review/Release/minhook_failure_review.exe 1
out-review/Release/minhook_failure_review.exe 2
out-review/Release/geometry_review.exe audit/fixtures/extreme_overflow.bin
```

The harness includes the unchanged runtime sources and only hooks its own
synthetic functions. MinHook fault injection is confined to a separate test
library. Geometry fixtures are synthetic, not game assets. Evidence is under
`audit/evidence`. Successful harness execution demonstrates current behavior,
including the defects; these are not regression tests asserting they are fixed.
The external-callee mutation was an additional data-only audit using the local
baseline executable; no executable bytes are redistributed.

## Recommended sequence

Close the compatibility/MinHook P1 risks first, then repair buffer accounting,
age/reset and geometry validation. Follow with allocation-failure handling,
reproducible regression tests, reload/battle testing and a real second game build.
Source publication is possible with these limitations documented; this candidate
should not be advertised as universally compatible with future patches.
